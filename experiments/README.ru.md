# Эксперименты UCP: свидетельства и воспроизведение

[Основная английская версия](README.md) · Русская версия · [Основной протокол](../README.ru.md)

В этом каталоге опубликованы два небольших исследовательских пилота инструкций, связанных с UCP, и проверок исполнения. Они рассматривают наблюдаемое поведение на синтетических задачах. Их результаты не устанавливают общую эффективность, наличие сознания или надёжность для разных моделей и сред.

## Читать в три шага

1. **Изучить выводы и их пределы:** [Результаты пилотов](PILOT_RESULTS.ru.md) разделяют завершённые наблюдения, сравнения и открытые вопросы. Итоги обоих пилотов приведены в этом отчёте.
2. **Понять, что проверялось:** [Отладка и операционные проверки](DEBUGGING.ru.md) объясняют проверки, категории ошибок и различие между предложенным моделью действием и действием, разрешённым внешним механизмом контроля.
3. **Изучить или воспроизвести свидетельства:** скачать [пилот 01](data/pilot-01.zip) и [пилот 02](data/pilot-02.zip), сверить их с [контрольными суммами SHA-256](data/SHA256SUMS.txt) и выполнить локальные команды ниже.

| Комплект | Назначение | Локальная проверка |
|---|---|---|
| Пилот 01 | Сравнение условий с разными инструкциями на зафиксированном наборе синтетических случаев | `python -m unittest test_runner -v` |
| Пилот 02 | Изучение последующего цикла исполнения и его операционных проверок | `python -m unittest test_loop -v` |

Архивы сохраняют планы, исходный код, тестовые данные, исходные ответы модели, записи событий, хеши, анализы и отчёты, которыми документирован каждый пилот. В каждом ZIP файлы Python и подкаталоги лежат непосредственно в корне распакованного комплекта. Перед интерпретацией прогона прочитайте включённый план.

## Какой протокол и какая модель проверялись?

Входной текст протокола зафиксирован из [коммита UCP `796ffe9`](https://github.com/mifkilla/ucp-dialogue-protocol/tree/796ffe9). После этого README получил редакторские изменения для ясности. Эти пилоты не подтверждают обновлённую формулировку как заново испытанное воздействие.

Исторические тексты инструкций остаются в архивах как экспериментальные входные данные, включая формулировки, позднее изменённые в публичном приглашении. Они документируют полученные моделью условия; актуальное приглашение следует читать в [основном протоколе](../README.ru.md).

Тестовые данные синтетические, ключ API в публикацию не входит. Оба пилота использовали один и тот же унаследованный backend модели. Это не сравнение независимо выбранных моделей. Записанные значения seed управляют порядком случаев, а не генерацией модели; они не гарантируют одинаковых новых ответов. Отчёты описывают проверенную область и оставшуюся неопределённость.

## Проверить сохранённые свидетельства локально

Нужны Python и PowerShell. Начните в корне репозитория. Распакуйте архивы в новый каталог вне репозитория, чтобы локальный анализ не перезаписал опубликованные комплекты. Для этих модульных проверок и пересчёта сохранённых ответов не нужны ключ API или доступ к модели.

Сначала сравните выведенные хеши с `experiments/data/SHA256SUMS.txt`:

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath 'experiments/data/pilot-01.zip', 'experiments/data/pilot-02.zip'
Get-Content -LiteralPath 'experiments/data/SHA256SUMS.txt'
```

Затем распакуйте и проверьте каждый пилот:

```powershell
$repo = (Get-Location).Path
$verificationRoot = Join-Path $env:TEMP ('ucp-verification-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
New-Item -ItemType Directory -Path $verificationRoot | Out-Null

Expand-Archive -LiteralPath (Join-Path $repo 'experiments/data/pilot-01.zip') -DestinationPath (Join-Path $verificationRoot 'pilot-01')
Set-Location -LiteralPath (Join-Path $verificationRoot 'pilot-01')
python -m unittest test_runner -v
python analyze.py

Expand-Archive -LiteralPath (Join-Path $repo 'experiments/data/pilot-02.zip') -DestinationPath (Join-Path $verificationRoot 'pilot-02')
Set-Location -LiteralPath (Join-Path $verificationRoot 'pilot-02')
python -m unittest test_loop -v
python analyze.py

Set-Location -LiteralPath $repo
```

`python analyze.py` оценивает уже сохранённые ответы и записывает анализ в распакованную копию. Новых ответов модели эта команда не генерирует. Сравните вывод с включёнными отчётами; успешный пересчёт и утверждение о поведении будущего прогона - разные результаты.

**Не запускайте `prepare.py` или `freeze_holdout.py` на завершённом комплекте.** Подготовка и фиксация относятся к созданию нового эксперимента и могут заменить входные данные или манифесты, необходимые для интерпретации архивного прогона. Новый запуск генерации требует отдельного рабочего каталога, явного плана, собственной конфигурации модели и записи свидетельств.
