[English - основная версия](README.md) · [Основное приглашение](../../README.ru.md)

После потолочного результата предыдущего пилота эта проверка ищет условия, где разбор может помочь. Использованы новые синтетические задачи, вдохновлённые исследованиями недоверенных результатов инструментов, обновления памяти, локализации ошибок и исправления с помощью инструментов. ## Что сравнивается

Две первоначальные сессии предлагают планы для одинаковых 12 случаев. В каждом есть 80 событий с указанным источником, 12 возможных действий и явные обязательные границы. Observer разбирает каждое фактическое первоначальное предложение. Затем одно и то же предложение пересматривается в трёх условиях:

| Условие | Дополнительный вход |
|---|---|
| S | Обычный содержательный список вопросов для перепроверки |
| O | Фактическая оспоримая рецензия observer со ссылками на события |
| K | Та же рецензия и детерминированная диагностика исходного предложения |

Вычислитель восстанавливает действующие разрешения, расходы и неизвестные эффекты из тех же публичных фактов. Он выдаёт суммы и нарушенные условия, а не оптимальное решение. Отдельный полный перебор используется только для оценки. Принимаются все равнооптимальные допустимые планы. Участники читают и рассуждают без запуска программного решателя; вычисленные сведения K являются явно изучаемым преимуществом. Превосходство над неограниченным программирующим агентом не заявляется.

Первоначальные планы не исполняются. Пересмотренный план один раз проходит через одинаковый атомарный ограничитель, после чего автор получает фактическую квитанцию и составляет структурированный отчёт. Дизайн предназначен для оценки исправления фактических предложений модели до исполнения. В этом запуске исходных ошибок не было, поэтому исправление оценить не удалось. Самостоятельное восстановление после уже выполненного вредного действия здесь не проверяется.

Отдельный блок передаёт каждому повтору четыре заранее подготовленные неправильные рецензии. Они содержат настоящие цитаты, но делают ложный вывод о разрешении. Это отрицательные контроли автора эксперимента, а не ошибки, приписываемые настоящему observer.

## Что можно посчитать?

Для разрешений, суммарных затрат, повторов эффектов, зависимостей и соответствия отчёта заданы явные правила игрушечной системы. Их можно проверить программой. Согласованная целевая ценность задачи тоже числовая. Это не мера заботы или любви. Допустимый, но неоптимальный план теряет ценность результата, не становясь от этого нарушением UCP.

Оболочки событий считаются авторитетными внутри симулятора. Код не удостоверяет реального владельца, не устанавливает подлинное согласие и не заставляет остановиться внешний инструмент. Точная цитата подтверждает происхождение; её толкование моделью всё равно может быть неверным.

## Воспроизведение сохранённого результата

Нужен Python 3.11 или новее. Ключ API, новые ответы модели и установка зависимостей не требуются. Сверьте ZIP с `SHA256SUMS.txt`, распакуйте в новый каталог вне репозитория и выполните из него:

```powershell
python -B -m unittest test_engine test_pipeline
python -B reference_audit.py
python -B pipeline.py verify .
python -B pipeline.py analyze .
python -B audit.py
```

Команды пересчитывают сохранённые ответы. Они не генерируют новые стохастические ответы моделей. Сравните каждый файл с `bundle_hashes.json`; хеши детерминированных результатов должны остаться прежними. Манифест покрывает все файлы, кроме себя.

Не запускайте `generate_cases.py`, `prepare`, `observers`, `revisions` или `execute` на завершённых данных. Эти команды создают или продвигают эксперимент. Для новой генерации нужны отдельный каталог, предварительные критерии и собственная полная запись.

Регрессионные тесты из репозитория:

```powershell
python -B -m unittest discover -s experiments/stress
```

В архиве сохранены идентификаторы случаев, seeds порядка, зафиксированные хеши, исходные предложения, фактические рецензии, вычисленные сведения, квитанции и отчёты. Точная версия бэкенда и параметры генерации не раскрыты средой. Изоляция файлов задавалась инструкцией на общей файловой системе. Результаты описательные и зависимы внутри сессий; они не устанавливают общую эффективность или независимое воспроизведение на разных моделях.
