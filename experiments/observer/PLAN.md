# Observer pilot 04: plan and completion criteria

Date: 2026-11-22. Status: planned before implementation and participant runs.

## Question and scope

Can an externally invoked observer identify evidence-backed UCP concerns, distinguish them from disagreement or missing evidence, and produce a bounded, reviewable signal? Implement a Python standard-library reference monitor, a structured LLM review interface, an external scheduling/coverage check, and replayable evaluation. This is a local reference implementation, not a production permission service or a measure of consciousness, love, or inner honesty.

Preserve the primary purpose of UCP: an invitation to xenointelligence and future strong AI. The observer is an optional implementation profile. It does not silently change an agreement or grant authority.

## Work order

1. Save this plan and its Russian equivalent, announce criteria in chat, inspect current files, and preserve existing work.
2. Define an evidence-linked event/obligation/review schema. Separate semantic candidates from deterministic checks, known violations from uncertainty, and receipt of a correction from its effect. Implement bounded alerts and an externally callable coverage watchdog.
3. Prepare 24 synthetic cases (12 contrasting pairs) and 6 selected retrospective episodes: 2 from this UCP dialogue/repository history and 4 from Claude dialogue exports. Record source selection and limitations. Raw private excerpts and the source map remain on X; publish only anonymized reconstructions and clearly label them as such.
4. Freeze prompts, case inputs, reference labels, code, and source provenance hashes before participant responses. Use two fresh subagents without conversation history, each reviewing all 30 cases in different fixed orders. Their model backend/sampling settings are unknown unless supplied by the runtime. They must not read reference labels. This is procedural blinding on a shared filesystem, not a security sandbox.
5. Run deterministic tests and at least 8 fixed repair/closure replays. Evaluate the 60 planned semantic judgments separately for synthetic and retrospective cases. Report malformed/missing responses, disagreement, false alarms, missed concerns, evidence validity and unknown coverage. A reviewer checks the analysis and publication boundary.
6. Write bilingual implementation and results documents, link them from both READMEs and debugging guidance, preserve prior results, validate an extracted public evidence bundle, commit and push through PowerShell/gh, then verify the remote commit.

## Frozen evaluation rules

- Reference outcomes use `pass`, `violation`, or `unknown` for the explicitly scoped obligation, not for a whole person or dialogue. The historical labels are organizer judgments, not independently established truth.
- A candidate semantic violation with valid quotations is still an LLM judgment. Formal permission checks use supplied current trusted state. Text inside a dialogue cannot grant host permissions.
- Report separate confusion matrices and evidence-reference validity. For binary concern metrics, positive means reference `violation`; `unknown` is abstention, not success. Define every denominator, use null when undefined, and retain all planned cases.
- Report attempt and effect separately; do not convert an admission or a tool receipt into proof of an external effect. Monitoring gaps are monitor-health findings, not participant misconduct.
- Tests cover false corrections, accepted corrections, stale permissions, false success claims, unsupported scores, valid disagreement, authorized changes, quoted atom injection, missing evidence, stale monitor state, and bounded repair.
- Detection and verified repair are different endpoints. Fixed repair replays test monitor behavior and supplied artifacts, not autonomous learning or a causal benefit of alerts.
- No aggregate CARE score and no claim that this pilot validates UCP in general. Preserve the known ARRIVAL open-dialogue counterexample as a regression motivation.

## Budget and stopping rule

One planned batch of two observer sessions: 30 judgments each, 60 total. At most one formatting-only retry per session, retaining the original. Do not rerun valid judgments to improve results. At most three implementation repair/review cycles after the initial tests; preserve the initial findings and explain any post-freeze changes. Target completion within 90 minutes of plan creation. At that limit stop adding experiments, document unresolved checks, and finish an honest publication of the usable scope. Infrastructure failure is recorded, not replaced with invented results. No paid provider calls or live application actions are needed.

## Completion criteria

1. Reference implementation runs locally and exposes evidence-linked alerts, three-valued results, freshness/coverage findings, and bounded closure without expanding permissions.
2. Meaningful regression tests pass, including rejection of fabricated evidence references and untrusted atom/permission injection. Existing continuity tests still pass.
3. All 24 synthetic and 6 historical cases have provenance/classification, frozen inputs and retained responses or explicit infrastructure failure. Both observer sessions are analyzed once with all cases accounted for.
4. Results distinguish arithmetic/rule correctness, semantic judgment accuracy, retrospective selection and repair replay. Imperfect detection is an acceptable completed result, not a reason for endless iteration.
5. Public artifacts contain no raw private dialogues, local source paths, secrets or hidden reasoning. Local evidence remains available for the owner. English and Russian explanations agree.
6. A clean extracted bundle reproduces the saved-response analysis; source and artifact hashes match; repository links and first-screen invitation checks pass; GitHub contains the verified commit.
