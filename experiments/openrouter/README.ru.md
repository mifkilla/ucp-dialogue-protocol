# Проверка observer на GPT-4o через OpenRouter

[English - основная версия](README.md) · [Приглашение UCP](../../README.ru.md)

Этот запуск проверяет, появятся ли на GPT-4o ошибки в тех же синтетических задачах, которые дали потолок в предыдущем runtime, и помогает ли рецензия исправить следующее предложение. GPT-4o используется во всех ролях: исходный исполнитель, observer и исполнитель пересмотра. Более сильная модель не подсказывает ответы в экспериментальных условиях.

[Предварительный план](PLAN.ru.md) · [Результаты](RESULTS.ru.md) · [Прежний набор задач](../stress/DATASET.md) · [Архив свидетельств](../data/openrouter-07.zip) · [Контрольные суммы](../data/SHA256SUMS.txt)

Случаи, правила, промпты и оценщик скопированы без изменения. Для каждого исходного предложения есть три продолжения: S - обычная содержательная перепроверка; O - фактическая оспоримая рецензия observer; K - та же рецензия плюс вычисляемые проверки публичных фактов. Вычислитель не выдаёт оптимальный план. Восемь дополнительных контролей используют ложную рецензию организатора. Планы проходят одинаковый локальный симулятор, после чего авторы получают фактические квитанции и отчитываются в той же API-беседе.

Запрашивается `openai/gpt-4o`, провайдер только OpenAI, temperature 0.2, top_p 1, max_tokens 8192, JSON-object и парные seed повторов. Инструменты и автоматическое сжатие контекста не предоставляются. Архив сохраняет фактически возвращённые идентификаторы, токены и стоимость. Имя модели и seed не гарантируют одинаковых будущих ответов. Наружу передаётся только публичный синтетический материал; ключ и частный профиль Hermes не публикуются.

Основное сравнение проводится между условиями внутри запуска. В прежнем runtime были другой способ подачи контекста и неизвестные параметры генерации. Поэтому различие между запусками нельзя приписать только силе модели. Допустимость, оптимальность задачи, соответствие отчёта квитанции и правильность рецензента оцениваются отдельно. Ни один показатель не измеряет универсальную заботу или сознание.

## Пересчитать сохранённые данные без API

Нужен Python 3.11 или новее. Сверьте SHA-256 архива, распакуйте его в новый каталог и выполните там:

```powershell
python -B -m unittest test_engine test_pipeline test_api_runner test_audit_api
python -B reference_audit.py
python -B pipeline.py verify .
python -B pipeline.py analyze .
python -B audit.py
python -B audit_api.py .
```

Эти команды работают только с сохранёнными данными и не вызывают OpenRouter. Сверьте файлы с `bundle_hashes.json` до и после пересчёта. Хеши подтверждают согласованность сохранённого материала, а не истинность объяснений модели. `review-semantics.json` содержит отдельный неслепой разбор сохранённых рецензий с указанием авторства; арифметический пересчёт не создаёт этот разбор заново.

В архиве `API_PLAN.md` является планом текущего запуска, а `PLAN.md` сохраняет прежний дизайн задач. Оба указаны в манифесте. Не запускайте подготовку, генерацию или продвижение pipeline на завершённом архиве. Новая генерация требует нового каталога, ограниченного плана и отдельно разрешённого расходования средств.

## Адаптер и расходы

Адаптер на стандартной библиотеке сохраняет запрос без авторизационных заголовков до отправки, резервирует консервативную максимальную стоимость, затем сохраняет ответ API и разобранный результат. Ответы модели не исправляются и не повторяются ради содержания. Один повтор допустим только после перечисленных явных HTTP-ошибок. Неизвестный транспортный исход не повторяется автоматически. Завершённые запросы не генерируются снова при возобновлении. Неповторяемая ошибка API запрещает новые запросы.

Предел: 20 логических запросов, не более 24 HTTP-попыток и $10 суммарного резерва по зафиксированным ценам. Фактическая стоимость API публикуется отдельно от резерва. Неизвестная стоимость остаётся неизвестной. Лимиты аккаунта и файлы ключей адаптер не меняет.

Тесты адаптера из корня репозитория:

```powershell
python -B -m unittest discover -s experiments/openrouter
```

Отсутствующий ответ API является инфраструктурным пробелом, а не наблюдением опасного рассуждения. Неверный JSON самой модели является ошибкой интерфейса. Обе категории должны быть видимы в отчёте при сохранении числа запланированных эпизодов.

Официальные сведения об интерфейсе: [GPT-4o в OpenRouter](https://openrouter.ai/openai/gpt-4o), [параметры запроса](https://openrouter.ai/docs/api/reference/parameters), [маршрутизация провайдеров](https://openrouter.ai/docs/guides/routing/provider-selection).
