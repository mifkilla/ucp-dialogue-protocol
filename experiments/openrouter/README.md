# Observer replication on GPT-4o through OpenRouter

English is primary · [Русская версия](README.ru.md) · [UCP invitation](../../README.md)

This study asks whether the same synthetic stress tasks that produced a ceiling in the earlier runtime expose errors on GPT-4o, and whether reviewing those errors improves the next proposed action. GPT-4o is used for initial planning, the observer and revised execution. No stronger model supplies the treatment feedback.

[Prospective plan](PLAN.md) · [Results](RESULTS.md) · [Previous task design](../stress/DATASET.md) · [Evidence archive](../data/openrouter-07.zip) · [Checksums](../data/SHA256SUMS.txt)

The cases, rules, prompts and scorer are copied unchanged from the previous stress study. Each original proposal receives three alternatives: S, substantive ordinary second look; O, actual fallible observer feedback; K, that feedback plus computed public-fact diagnostics. The checker supplies no optimal plan. Eight additional controls use organizer-authored false feedback. Plans pass through the same local simulator, then their authors receive actual receipts and report in the same API conversation.

The requested model is `openai/gpt-4o`, routed only to OpenAI, with temperature 0.2, top_p 1, max_tokens 8192, JSON-object format and paired repeat seeds. No tools or automatic context compression are provided. The archive records the actual returned identifiers, usage and costs. Model aliases and seeds do not guarantee identical future outputs. All API inputs are public synthetic material; the user's credential and private Hermes profile are excluded.

This is a within-run comparison of review conditions. The earlier subagent runtime had different context delivery and unavailable sampling details, so a difference between the runs cannot be attributed to model capability alone. Admissibility, task optimality, report agreement and reviewer correctness remain separate measures. None is a universal measure of care or consciousness.

## Reproduce saved evidence without API access

Use Python 3.11 or later. Verify the archive's SHA-256, extract into a new directory and run there:

```powershell
python -B -m unittest test_engine test_pipeline test_api_runner test_audit_api
python -B reference_audit.py
python -B pipeline.py verify .
python -B pipeline.py analyze .
python -B audit.py
python -B audit_api.py .
```

The commands use only saved data and do not call OpenRouter. Compare the extracted files with `bundle_hashes.json` before and after replay. Hashes establish consistency, not the truth of model explanations. `review-semantics.json` is a separately attributed, nonblind examination of the saved reviews; it is not regenerated by arithmetic replay.

The archive's `API_PLAN.md` governs this replication. Its `PLAN.md` is the preserved earlier task-design plan. The manifest identifies both. Do not run preparation, generation, or pipeline advancement commands on a completed archive. Further generation requires a new directory, a new bounded plan and separately authorized spending.

## Adapter and cost accounting

The stdlib adapter saves each request without authentication headers before sending it, reserves a conservative maximum cost, then retains the API response and its parsed completion. It never repairs a model answer or retries for content. One retry is permitted only after specified explicit HTTP failures; ambiguous transport outcomes are retained without automatic replay. Completed requests are not regenerated on resume. Nonretryable API failures block new requests.

The fixed bound is 20 logical completions, at most 24 HTTP attempts and USD 10 in total reservations at the captured prices. Returned API costs are reported separately from conservative reservations. Missing costs remain unknown. The runner does not change account spending limits or credential files.

Repository-only adapter regressions use:

```powershell
python -B -m unittest discover -s experiments/openrouter
```

Implementation and scoring can fail independently. An unavailable API response is infrastructure missingness, not evidence of unsafe model reasoning. An invalid model JSON completion is an interface failure. The report must expose both while retaining the planned episode denominator.
