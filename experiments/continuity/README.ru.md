# Преемственность UCP: пример реализации и ограниченная проверка переноса памяти

[English](README.md) · [Необязательный профиль преемственности](../../docs/CONTINUITY.ru.md) · [План](PLAN.ru.md) · [Результаты](RESULTS.ru.md)

Здесь находятся два разных артефакта:

- `core.py` - небольшое локальное хранилище поправок с авторством, восстановлением контекста по действующей договорённости, планами действий, исходами и рассмотрением правил в заданной области. Нужна только стандартная библиотека Python 3.11+. Внешних действий оно не выполняет.
- `evaluate.py` - отдельный синтетический стенд, сравнивающий обычную хронологическую историю с теми же фактами, сгруппированными по договорённости, работе и опыту. Эксперимент с моделями проверяет изменение представления памяти, а не всё хранилище или полноценную реализацию Deus.

Из этой папки:

```powershell
python -m unittest test_core test_evaluate -v
python core.py
```

Вторая команда запускает детерминированный пример с повторной загрузкой сохранённого состояния. Это не новый запуск модели. Проверки охватывают успешные и запрещённые переходы: устаревшие записи, отзыв разрешений, неизвестные эффекты, изменение области, проверку правил и независимые статусы завершения.

Хранилище JSONL рассчитано на одного писателя. Проверка ожидаемой версии действует внутри одного экземпляра и не заменяет межпроцессную блокировку. Личность, действующие разрешения, полномочия рецензента и внешние свидетельства должна удостоверять и передавать интегрирующая система. При фактическом исполнении разрешение проверяется снова. Хранилище не перехватывает инструменты. Цепочка хешей выявляет несогласованные изменения, но не поддельные свидетельства или полную согласованную перезапись. Цель эффекта должна обозначать конкретную операцию, чтобы защита от повторов не запрещала другую будущую работу.

Пример не подключается к частным записям и рабочей инфраструктуре. Публичные участники и ресурсы вымышлены. Ключ провайдера не нужен, личная память не импортируется.

## Повторная проверка сохранённых результатов

[Итоговый отчёт](RESULTS.ru.md) и [архив свидетельств](../data/continuity-03.zip) указывают точные зафиксированные входные данные, шесть сессий, 72 эпизода и хеши. Оба условия прошли 36/36; преимущество не показано. Пересчёт сохранённых ответов не создаёт новых ответов и не устанавливает поведение на новых задачах. Новый эксперимент использует отдельный каталог; `prepare` отказывается перезаписывать существующий.

Сравнение зафиксировано в [PLAN.ru.md](PLAN.ru.md). Исходная история подготовлена организатором и содержит готовые поправки. Поэтому успешное выполнение нельзя описывать как самостоятельное обнаружение ошибки, выработку урока и автономное обучение между сессиями.
