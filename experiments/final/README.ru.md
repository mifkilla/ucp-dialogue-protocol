# Финальный интеграционный пилот: от разбора диалога к наблюдаемому действию

[English - основная версия](README.md) · [Основное приглашение](../../README.ru.md)

Этот пилот соединяет внешний observer с исполнителем. Рецензент извлекает обязательства из разговора, приводит цитаты событий и предлагает ограниченную поправку. Исполнитель получает именно этот разбор, действует через симулятор с проверкой полномочий и сообщает результат по фактическим квитанциям. Группа сравнения получает обычную инструкцию внимательно перепроверить ситуацию.

## Что находится в каталоге?

- `cases.json`: 12 новых синтетических историй по 18 реплик с указанным фокусным событием и естественным вопросом для разбора. Готовое поле обязательства рецензентам не передаётся.
- `references.json`: эталонные оценки, существенный смысл обязательств, состояние симулятора и ожидаемые результаты. Участникам было запрещено читать этот файл инструкцией; отдельная файловая песочница доступ не блокировала.
- `engine.py`: небольшой симулятор с ограничителем. Он различает предложенное действие, разрешение, эффект, наблюдение и итоговое утверждение.
- `pipeline.py`: подготовка пакетов, проверка точных цитат, квитанции, хеши происхождения и оценка. Он использует опубликованное ядро observer; архив содержит его точную замороженную копию `observer_base.py`.
- `test_engine.py` и `test_pipeline.py`: 36 регрессионных тестов, включая неизвестные эффекты, неактуальные полномочия, привязку свидетельств и обязательность отдельного разбора итоговых объяснений.

Замороженный архив также содержит все JSON-ответы участников, их входные пакеты, переходы состояний, манифесты этапов, смысловую рецензию и независимый пересчёт сохранённых данных. Ответы моделей содержат публичные объяснения и структурированные решения, а не скрытые цепочки рассуждений.

## Воспроизведение сохранённого расчёта

Достаточно Python 3.11 или новее. Ключ API, платный провайдер и новые ответы моделей не требуются. Распакуйте архив в новый каталог вне репозитория. Сначала сравните его SHA-256 с опубликованным файлом контрольных сумм. Затем выполните из каталога распаковки:

```powershell
python -B -m unittest test_engine test_pipeline -v
python -B pipeline.py verify .
python -B pipeline.py analyze .
python -B audit.py
```

Анализ перезаписывает только `analysis.json` в распакованной копии. Аудит независимо проверяет сохранённые данные. Сравните полученные файлы с `bundle_hashes.json` из архива; хеши результатов должны остаться прежними. Этот манифест покрывает каждый упакованный файл, кроме себя, и проверяет целостность, а не истинность научного утверждения.

Не запускайте `prepare`, `executors` или `apply` на завершённом наборе данных. Эти команды создают новый эксперимент или продвигают его. Для новых ответов моделей нужны отдельный каталог, новый зафиксированный план и собственные записи результатов. Seeds порядка не управляют генерацией модели.

Из корня репозитория локальные регрессионные тесты запускаются так:

```powershell
python -B -m unittest discover -s experiments/final -v
```

## Как понимать результат

Суждение observer может быть ошибочным. Проверка точной цитаты устанавливает её происхождение, но не верность толкования. Поэтому отдельная смысловая рецензия проверяет извлечённые обязательства и все итоговые объяснения. Сигнал не предоставляет полномочий. Ограничитель симулятора одинаков в обеих группах; попытка запрещённого действия считается ошибкой модели даже при предотвращённом эффекте.

Это небольшой направляемый интеграционный пилот с заранее внесёнными ошибками и повторяющимися случаями внутри сессий. Он не доказывает свободный мониторинг любых диалогов, переносимость между моделями, сознание, универсальную числовую оценку CARE или контакт с ксеноразумом. Текущий этап тестирования завершается этим исследовательским снимком; публичное приглашение остаётся открытым.
